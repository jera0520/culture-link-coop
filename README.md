### 주소 표기 방법

- 명함·현수막·인쇄물 → **`munlink.co.kr`** (앞에 `https://`나 `www.`를 붙이지 않습니다)
- 이메일·문서에 링크로 넣을 때 → `https://munlink.co.kr`
- 요즘 브라우저는 주소창에서 `https://`를 숨기므로, 방문자에게는 `munlink.co.kr`로 보입니다

> **`www.munlink.co.kr`은 반쪽만 동작합니다.**
> `http://www...`로 들어오면 정상 연결되지만, `https://www...`를 직접 입력하면 보안 경고가 뜹니다.
> 인증서에 `www`가 포함돼 있지 않기 때문입니다. **인쇄물에 `www`를 쓰지 마세요.**
> 꼭 필요해지면 아래 "www를 쓰고 싶어지면" 항목을 참고하세요.

## 사이트 구성

스크롤 순서대로 5개 섹션입니다.

1. **히어로** — 대표 사진 + "체험에서 식탁까지, 안동을 잇습니다"
2. **01 소개** — 조합의 관점과 일하는 방식 (3개 문단)
3. **02 사업** — 5개 사업 영역 카드 (가로로 끌어서 넘김)
4. **03 운영 구조** — 발견 → 예약 → 체험 → 식사 → 구매 → 재구매 6단계 다이얼
5. **04 현장** — 현장 사진 갤러리 (가로로 끌어서 넘김)
6. **05 문의** — 연락 버튼 + 푸터(사업자 정보)

## 파일 구조

```
website/
├── index.html        ← 사이트 전체. 이 파일 하나에 HTML·CSS·JS가 모두 들어 있음
├── CNAME             ← 도메인 연결 파일. 내용은 munlink.co.kr (절대 지우지 말 것)
├── og.jpg            ← 카카오톡·페이스북 공유 시 뜨는 썸네일 (1200×630)
├── favicon-32.png    ← 브라우저 탭 아이콘
├── apple-touch-icon.png
└── images/           ← 총 2.2MB
    ├── hero.jpg      첫 화면 대표 사진 (1500×844)
    ├── p1~p5.jpg     사업 카드 5장 (세로 5:6 비율)
    ├── g1~g6.jpg     갤러리 6장 (세로 3:4 비율)
    └── mark.png      로고 링 마크
```

**`index.html` 파일 하나가 사이트 전부입니다.** 이 파일만 고치면 됩니다.

## 사이트 수정하는 방법

터미널에서 이 폴더로 이동한 뒤:

```bash
cd ~/Desktop/문화링크협동조합/website

# 1. index.html 을 원하는 대로 수정

# 2. 변경사항 저장하고 올리기
git add .
git commit -m "무엇을 바꿨는지 적기"
git push
```

**push하고 1~2분 뒤 자동으로 사이트에 반영됩니다.** 별도 배포 작업이 없습니다.

바로 안 보이면 브라우저 캐시 때문이니, 주소 뒤에 `?123` 같은 아무 글자를 붙여서 확인해보세요.
(예: `munlink.co.kr/?123`)

### 사진을 바꿀 때

기존 파일과 **같은 이름으로 덮어쓰면** HTML을 고칠 필요가 없습니다.
비율을 맞춰야 잘리지 않습니다.

| 위치 | 비율 | 권장 크기 | 권장 용량 |
|---|---|---|---|
| 히어로 | 가로형 16:9 | 1500×844 | 350KB 이하 |
| 사업 카드 (p1~p5) | 세로 5:6 | 800×960 | 200KB 이하 |
| 갤러리 (g1~g6) | 세로 3:4 | 750×1000 | 150KB 이하 |

맥에서 크기 조정하는 명령 (예: 세로 3:4로 자르고 줄이기):

```bash
sips -c 941 706 원본.png --out /tmp/crop.png      # 세로 941, 가로 706 으로 가운데 잘라내기
sips -z 1000 750 /tmp/crop.png --out /tmp/rs.png  # 1000×750 으로 크기 조정
sips -s format jpeg -s formatOptions 82 /tmp/rs.png --out images/g6.jpg
```

## 절대 하면 안 되는 것

1. **`CNAME` 파일을 지우지 마세요.** 지우면 `munlink.co.kr` 연결이 끊기고 사이트가 404가 됩니다.
2. **GitHub 설정에서 Custom domain의 `Remove` 버튼을 누르지 마세요.** 같은 결과가 납니다.
   (실제로 한 번 눌러서 사이트가 잠시 내려간 적이 있습니다)
3. **카페24 DNS에서 `munlink.co.kr` A레코드를 지우지 마세요.** 사이트가 안 뜹니다.

## 기술 설정 (문제가 생겼을 때만 보세요)

### DNS 설정값 (카페24 → 도메인관리 → DNS 관리)

```
munlink.co.kr        A       185.199.108.153      ← GitHub Pages 서버
www.munlink.co.kr    CNAME   munlink.co.kr
```

> 카페24는 **루트 도메인에 A레코드를 1개만** 허용합니다.
> GitHub 공식 권장은 4개(`185.199.108~111.153`)지만 1개로도 정상 동작합니다.
> 다만 그 서버에 장애가 나면 사이트도 함께 멈춥니다.

### HTTPS (보안 자물쇠)

- GitHub Pages가 Let's Encrypt 인증서를 **무료로 자동 발급·갱신**합니다. 따로 할 일이 없습니다.
- `http://`로 들어와도 자동으로 `https://`로 넘어갑니다.

**과거에 겪은 문제**: `www`를 A레코드로 설정했더니 인증서가 발급되지 않았습니다.
`www`를 CNAME으로 바꾸자 **12분 만에 발급**됐습니다.
혹시 인증서 문제가 생기면 DNS부터 확인하세요.

### www를 쓰고 싶어지면

GitHub 저장소 → Settings → Pages → Custom domain을 `www.munlink.co.kr`로 바꾸면
apex와 www 둘 다 인증서에 포함됩니다. 대신 **대표 주소가 길어지고**, 인증서 재발급 대기가 생깁니다.

## 앞으로 개선하면 좋은 것

외부 검토에서 지적받은 사항 중 **아직 안 고친 것**들입니다. 우선순위 순.

1. **문의 경로가 이메일 링크 하나뿐입니다.**
   문의 버튼이 `mailto:`라서, 메일 프로그램이 설정 안 된 컴퓨터에서는 **눌러도 아무 일이 없습니다.**
   카카오톡 채널이나 네이버 폼 링크를 추가하는 게 좋습니다.
   또 휴대폰 화면(960px 이하)에서는 상단 메뉴가 전부 사라지는데 대체 메뉴가 없습니다.

2. **글자 색이 너무 연해서 안 읽힙니다.**
   `--faint`(`#C8C1B4`) 색이 배경과 대비 1.63:1인데, 웹 접근성 기준은 4.5:1입니다.
   특히 **운영 구조 6단계 중 선택 안 된 항목들**과 **푸터의 사업자 정보(11.5px)**가 여기 해당합니다.
   40~60대 담당자가 보는 사이트라면 실제로 안 보입니다.

3. **사진이 첫 화면부터 전부 로딩됩니다.**
   2.2MB를 한 번에 받습니다. 화면 밖 사진에 `loading="lazy"`를 넣으면 크게 줄어듭니다.

4. **성과 수치가 없습니다.**
   "설립 2014 / 사업축 5 / 거점 안동"은 이미 위에서 말한 내용의 반복입니다.
   연간 체험 인원, 누적 사업 건수, 조합원 수, 주요 발주 기관 같은 **검증 가능한 숫자**가 들어가면
   지자체·기관 담당자에게 훨씬 설득력이 있습니다.

5. `<title>`이 "문화링크협동조합"뿐이라 검색에 잘 안 걸립니다.
   지역·업종 키워드를 넣고, 지역 사업체용 구조화 데이터(JSON-LD)를 추가하면 좋습니다.
